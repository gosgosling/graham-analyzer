# Тесты расчётного слоя

## Как запускать

Из каталога `backend`:

```bash
venv/bin/python -m pytest          # весь набор, ~1.5 с
venv/bin/python -m pytest -k fcf   # только по подстроке в имени теста
```

Базу данных, LLM и сеть тесты не используют. Отчёт подменяется заглушкой
(`tests/conftest.py`), потому что расчётный слой читает атрибуты объекта и ему
безразлично, ORM это или `SimpleNamespace`. За счёт этого тесты не ломаются от
миграций схемы.

## Что покрыто

| Файл | Что проверяет |
| --- | --- |
| `test_calc_multipliers.py` | P/E, P/B, ROE, D/E, Current Ratio, дивидендная доходность (общая и регулярная), FCF-цепочка, ветка банка, отчёт в USD/EUR |
| `test_fcf_and_shares.py` | формула FCF, чистый долг, приоритет полей количества акций, пояснение базы капитализации |
| `test_ltm.py` | формула LTM = FY + YTD − prior YTD, дивиденды, сложение кварталов, откат валюты перед calc_multipliers |
| `test_currency.py` | конвертация RUB/USD/EUR/CNY в рубли |
| `test_sector_profiles.py` | подбор профиля по строке сектора, ручное закрепление, оценка значения по порогам, сериализация для фронта |
| `test_graham_analyser.py` | итоговый вердикт: только применимые метрики, отраслевые пороги, CIR у банков |
| `test_extraction.py` | пересчёт единиц из PDF, страховки над ответом модели, предупреждения аналитику, отбор страниц PDF |

Числа в базовой заглушке подобраны круглыми (капитализация 100 млрд ₽, прибыль
10 млрд, капитал 50 млрд), чтобы ожидаемые P/E = 10, P/B = 2, ROE = 20%
проверялись в уме, а не пересчитывались калькулятором.

## Что НЕ покрыто (задел на следующие итерации)

1. **`get_ltm_data` целиком** — выбор ветки «годовой / interim-формула /
   сумма 4 кварталов» через Postgres. Чистая арифметика LTM уже в
   `test_ltm.py`; для полного пути нужен SQLite in-memory или выделение
   оркестрации без `Session`.
2. **Запись отчёта** (`services/reports/report_service.py`) — проверка, что
   `create_report` и `update_report` не теряют поля. Нужна сессия.
3. **Нормализация и справедливая стоимость** — писать вместе с самим
   функционалом: средние за 3/5/7 лет, число Грэма, NCAV, формула 1962 года.
   Каждая формула проверяется на примере из «Разумного инвестора».
4. **Фронтовые утилиты** (`roeBreakdown.ts`, `sectorProfile.ts`) — отдельный
   Vitest/Jest, когда дойдёте до CI на frontend.

## Качество ИИ-извлечения (эталоны LKOH / NVTK)

Эталоны — вручную заполненные `verified_by_analyst` отчёты **ЛУКОЙЛа** и
**НОВАТЭКа**, выгруженные в `tests/fixtures/golden/`.

```bash
# обновить фикстуры из живой БД
venv/bin/python scripts/export_golden_reports.py

# офлайн-тесты сравнения (LLM не нужен) — всегда в CI
venv/bin/python -m pytest tests/test_extraction_quality.py

# живой прогон модели по PDF (нужны файлы LKOH_2024.pdf и т.п.)
GOLDEN_PDF_DIR=/path/to/pdfs EXTRACTION_MIN_SCORE=0.70 \
  venv/bin/python -m pytest -m live_extraction -v
```

Офлайн-набор проверяет, что `compute_report_diff` правильно ловит типичные
ошибки модели (акции ÷1000, пропавшая амортизация, «Итого капитал и
обязательства» вместо обязательств) и что идеальное совпадение даёт score=100%.

Живой прогон — уже метрика качества парсинга. Без PDF тест пропускается
(`skipped`), CI не краснеет. В UI тот же инструмент: `POST /reports/compare-pdf`.

На что смотреть в первую очередь при ручном разборе:

* `mismatch` по `total_liabilities` / `current_*` — строка-заголовок вместо «Итого»;
* `missing_ai` по `depreciation_amortization` — не дошла страница ОДДС;
* акции кратно 1000 — не учтена подпись «(тыс. штук)»;
* `net_income` ≠ `net_income_reported` — нормализация по Грэму всегда на ревью.
