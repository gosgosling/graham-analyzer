## 🎯 Как протестировать

### 1. Список компаний
1. Откройте http://localhost:5173/companies
2. Вы должны увидеть таблицу с компаниями
3. У каждой компании есть кнопка **▶** в начале строки
4. Нажмите на **▶** - откроется секция с отчётами
5. Если отчётов нет, вы увидите кнопку "Добавить первый отчет"

### 2. Переход на страницу компании
1. Нажмите на **любую строку компании** в таблице
2. Вы перейдёте на `/company/{id}`
3. На странице отобразится:
   - Название компании
   - Тикер и сектор
   - Основная информация (FIGI, ISIN)
   - Список финансовых отчётов (если есть)
   - Цена акции и капитализация (если есть отчёты)

### 3. Проверка бэкенда
```bash
# Получить компанию по ID (например, ID=5)
curl http://localhost:8000/companies/5

# Получить список всех компаний
curl http://localhost:8000/companies/

# Получить отчёты компании
curl http://localhost:8000/reports/company/5
```

## 🤖 Автотесты

```bash
cd backend && venv/bin/python -m pytest        # расчётный слой и сервисы
cd frontend && CI=true npm test                # чистая логика фронтенда
```

Фронтенд тестирует только модули `src/utils` — формулы, продублированные с
бэкенда (FCF, чистый долг, выбор акций, форматирование копеечных цен). Теста,
который рендерит `App` целиком, здесь нет намеренно: react-scripts 5 приносит
jest 27, который не читает поле `exports` в package.json, а `react-router` 7,
`antd` 6 и `recharts` 3 объявляют точки входа только через него. Заставить это
работать можно лишь цепочкой подмен путей к внутренним файлам чужих пакетов —
она ломается при каждом обновлении. Проверку «приложение вообще собирается»
делает `npm run build`, и её достаточно.

Если понадобится тест компонента, дешевле сначала переехать с react-scripts на
Vite + Vitest, чем чинить jest 27.
