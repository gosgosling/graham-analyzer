# Доступ и безопасность

Сайт открыт всем **на чтение**, аккаунт для этого не нужен. Аккаунты — для
будущих функций сообщества. Менять данные проекта (отчёты, парсинг,
синхронизация) может только пользователь с ролью `admin`.

## Аккаунты

| Что | Как | Почему |
|---|---|---|
| Регистрация | почта + имя + пароль, согласие на обработку данных; сразу входит, на почту уходит ссылка подтверждения (48 ч) | войти можно и без подтверждения; то, что потребует доверия к адресу, проверит отметку |
| Пароль | от 10 до 128 символов, не из списка частых, без почты и имени внутри; состав («цифра и спецсимвол») не требуем | NIST SP 800-63B: длина важнее состава |
| Хранение пароля | только хэш scrypt (N=2^17, r=8, p=1), соль своя, сравнение за постоянное время | утечка таблицы не раскрывает пароли, перебор хэша дорог |
| Вход | ошибка одна на «нет такой почты» и «неверный пароль»; для несуществующей почты пароль сверяется с хэшем-пустышкой | ни по тексту, ни по времени ответа не видно, кто зарегистрирован |
| Восстановление | `/auth/password/forgot` отвечает одинаково для любой почты; ссылка одноразовая, 30 минут; новый пароль закрывает все сессии | украденную сессию сброс пароля обрывает |
| Ссылки из писем | в письме случайная строка (256 бит), в базе — её SHA-256; новая ссылка гасит прежние | утечка таблицы не даёт ссылок |
| Смена пароля | нужен текущий пароль; закрывает все сессии, кроме текущей | — |
| Смена почты | нужен пароль; ссылка (24 ч) уходит на новый адрес, почта меняется только по ней; прежний адрес получает уведомление | опечатка не запирает аккаунт, угон через смену почты заметен |
| Удаление | по паролю, сразу и целиком (сессии и ссылки — каскадом); последнего администратора удалить нельзя | — |
| Роль admin | только скриптом на сервере, через сайт не выдаётся | — |

## Сессии и запросы

| Что | Как | Почему |
|---|---|---|
| Сессия | при каждом входе новая запись в `user_sessions`; в браузер — случайный идентификатор (256 бит) в cookie `ga_session` | в базе только SHA-256 идентификатора: утечка таблицы не даёт войти; новый идентификатор при входе — защита от фиксации сессии |
| Cookie | `HttpOnly`, `SameSite=Strict`, `Path=/`, `Secure` при `COOKIE_SECURE=true` | скрипт страницы cookie не видит (XSS не уносит сессию), чужой сайт её не пошлёт |
| Срок | 12 часов абсолютный, 2 часа простоя (`SESSION_TTL_HOURS`, `SESSION_IDLE_MINUTES`) | забытая вкладка закрывается сама |
| Выход | удаляет сессию на сервере и cookie; «выйти на всех устройствах, кроме этого» — остальные сессии пользователя; истёкшие сессии и ссылки удаляются ежечасно | отзыв — не «забыть в браузере», а убить на сервере |
| Перебор | вход: 5 неудач на почту и 10 на адрес за 15 минут → 429; каждая неудача отвечает через секунду. Регистрация — 5 в час с адреса, письма — 5 в час с адреса и 3 на почту | словарная атака бессмысленна, нас нельзя использовать как спамер |
| CSRF | на любой запрос, меняющий данные (включая вход и регистрацию): `Origin`/`Referer` из `ALLOWED_ORIGINS` + заголовок `X-Requested-With: graham-analyzer` | форма с чужого сайта заголовок поставить не может; скрипт — только с разрешения CORS |
| Доступ | одна прослойка (`app/utils/admin_guard.py`): `/auth/*` проверяет себя сам; всё остальное, кроме GET/HEAD/OPTIONS, и служебные разделы (`/admin`, `/mass-parse`, `/bonds`, `/securities`, прокси к Мосбирже, сводки раскрытий) — только роль admin (без входа 401, без роли 403) | новый эндпоинт на запись закрыт сам |
| Возврат после входа | `?next=` принимает только свой путь (`/…`, не `//…`) | нельзя увести на чужой сайт после входа |
| CORS | только источники из `ALLOWED_ORIGINS`, с учётными данными, явный список методов и заголовков | — |
| Заголовки | `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`, `CORP: same-site`, `Cache-Control: no-store` на `/auth/*`, HSTS при `COOKIE_SECURE` | — |
| Документация API | `/docs`, `/redoc`, `/openapi.json` — только при `DEBUG=true` | в бою это карта всех эндпоинтов |
| Журнал | логгер `auth`: регистрации, входы, неудачи, блокировки, смена пароля, удаление, отклонённые CSRF, попытки не-админа и каждое действие администратора; пароли не пишутся никогда, адреса почты — только в режиме без SMTP (вместе с письмом) | видно, кто и что менял |

Скрывать кнопки на фронтенде — удобство, а не защита. Решает сервер.

## Управление

```
python -m scripts.create_admin                 # создать администратора (спросит почту, имя, пароль)
python -m scripts.create_admin --promote MAIL  # дать роль уже зарегистрированному
python -m scripts.create_admin --demote MAIL   # снять роль (последнего — нельзя)
python -m scripts.create_admin --revoke        # закрыть все сессии всех пользователей
```

## Почта

Яндекс: `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465` (TLS сразу; для 587 —
STARTTLS), `SMTP_USER` и `SMTP_FROM` — один и тот же адрес ящика,
`SMTP_PASSWORD` — пароль приложения (id.yandex.ru → Безопасность → Пароли
приложений), не основной. Проверка: `python -m scripts.check_mail адрес`.
Ссылки в письмах строятся от `PUBLIC_SITE_URL`.

Без `SMTP_HOST` и `SMTP_FROM` письма не уходят, а пишутся в журнал сервера
вместе со ссылкой — локально так можно пройти весь путь.

## Перед выкладкой на сервер

- [ ] `DEBUG=false` — закрывает документацию API.
- [ ] `COOKIE_SECURE=true` и сайт только по https.
- [ ] `ALLOWED_ORIGINS=https://адрес-сайта`, `PUBLIC_SITE_URL=https://адрес-сайта`.
- [ ] SMTP настроен, письмо восстановления доходит (и не в «Спам»: SPF/DKIM у домена отправителя).
- [ ] Администратор создан на сервере своим запуском `create_admin` (не переносить базу пользователей с локальной машины).
- [ ] uvicorn за nginx — с `--proxy-headers --forwarded-allow-ips=127.0.0.1`, иначе все гости для ограничителя попыток — один адрес, и один перебор заблокирует вход всем.
- [ ] Один процесс uvicorn, или счётчики попыток перенести в Redis.
- [ ] Адрес API во фронтенде — не `http://localhost:8000` (`services/companies.api.ts`).
- [ ] CSP и прочие заголовки для статики фронтенда — в nginx.
- [ ] Список оператора из [PERSONAL_DATA.md](PERSONAL_DATA.md) закрыт.
